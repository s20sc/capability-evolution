# Experience source preparation and recorded-data reconstruction

The experience/ modules retain the original scientific source-preparation, bounded generation, atomic transition recorder and correction-pack construction. Source preparation uses only the first ten demonstrations in the fixed 160 learning partition, excluding the twenty internal-development demonstrations. Generation retains the original native task/controller, guards, per-case limits and five consecutive successful steps; the generator's anytime-success flag is insufficient for learning admission. Parent data are produced by Square100000, not the later D101000 child.

The five operations in run_experience.py use a fresh output directory and the SHA-256 of PACKAGE_IDENTITIES.json. Use Python -I -B, CUDA_VISIBLE_DEVICES='', and the native stack in DEPENDENCIES.md. The dependency directory is selected with --vendor; no installation or download occurs in these entry points. The original MimicGen source companion is selected with --mimicgen-source. Its NVIDIA terms and original notices remain applicable. The unmodified vendor-support files preserve the original gdown/BeautifulSoup/SoupSieve/PySocks sources and notices. generation-import-requirements.txt records currently observed additional import-support versions; it is not a claim of a historically frozen complete environment.

For prepare-source, supply --input-map with metadata_Square and raw_Square objects containing path and sha256. For generate-target or generate-correction, supply metadata_Square and the original prepared_source identity. The fixed profiles and hashes are in experience/recipes.json. Source preparation writes source10.hdf5. The saved-record reconstruction pathway is separate from native source preparation and collection.

The original record companion contains target/ and correction/ directories and parent/. For repack-target, pass --records /absolute/records/target. For repack-correction, pass --records /absolute/records/correction and --parent-log-map pointing to a JSON mapping the five seed strings to original parent path/sha256 objects; RECORD_IDENTITIES.json supplies the fixed relative mapping. Repacking reads actual returned transitions and the original parent logs; it does not run the generator, policy, environment or learner.

Example: CUDA_VISIBLE_DEVICES='' python3 -I -B run_experience.py repack-target /absolute/new-target --records /absolute/records/target --vendor /absolute/runtime --manifest-sha256 MANIFEST_SHA --seconds 30. Replace repack-target with repack-correction, use a separate workspace and the correction records plus parent map for the four correction arrays. Target output must match the original three-episode, 480-row array. The correction arms preserve LP/FP/LG/FG membership, order and generated-to-parent fallback; they do not introduce a new selection method.

The original method deadlines and operation caps remain in the fixed profiles. Entry wall checks are cooperative; use an external process watchdog for hard deadlines, including repacking and native library calls. Returned status, expected complete cases/partitions and actual output identities are all necessary. A partial directory or successful import alone is not completed generation or whole-study reproduction.
